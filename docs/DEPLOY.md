# Публикация демостенда

Владелец: Естай. Не требует доступа Бекзат к VPS. GitHub — источник кода;
деплой — отдельная проверяемая операция с SHA коммита. GitHub Actions сейчас
заблокирован внешним billing и не используется для выкладки.

`ops/deploy_vps.py` рассчитан на уже подготовленный односерверный k3s,
namespace/deployment `hackalem-qnt`, существующие TLS/Ingress/Service/Secret.
Это не универсальный установщик нового VPS. Он не перезапускает кластер и
не меняет остальные приложения. SSH host key должен быть заранее проверен.

```bash
# В чистом рабочем дереве после тестов, коммита и push:
.venv/bin/python ops/deploy_vps.py build --host USER@HOST --revision COMMIT_SHA
# На VPS: kubectl -n hackalem-qnt logs job/build-qnt-SHORT_SHA
# Продолжать только если Job завершился успешно:
.venv/bin/python ops/deploy_vps.py release --host USER@HOST --revision COMMIT_SHA --enable-ai
# На VPS: kubectl -n hackalem-qnt rollout status deployment/hackalem-qnt
```

Исходники передаются через `git archive` по SSH: локальные `.env`, node_modules,
неотслеживаемые файлы и учётные данные GitHub туда не попадают. Сборщик закреплён
по digest и использует Node 22 / Python 3.12 из Dockerfile. Итоговый образ
импортируется в containerd на единственном узле. В многосерверном кластере нужен
registry или доставка образа на каждый подходящий узел.

Флаг `--enable-ai` отдельно передаёт локальный ключ через stdin защищённого SSH
в существующий Kubernetes Secret. Ключ не входит в образ/аргументы команд/логи.
Без этого флага выпуск работает без платных запросов. HTTPS остаётся обязательным.

## Защита расходов

- На демо максимум **100 попыток обращения** к OpenAI всего, включая ошибки и таймауты.
- Счётчик SQLite хранится в PVC `qnt-ai-usage`, а не в эфемерном контейнере.
- Перезапуск и новая версия не сбрасывают счётчик. Нет публичной команды сброса.
- При лимите или проблеме хранилища выдача продолжает работать в режиме `local`.
- Уже закешированные AI-объяснения продолжают работать без дополнительного вызова.
- Два одновременных AI-запроса, до 12 в минуту на процесс, максимум 400 токенов ответа.
- Это ограничение количества вызовов данного приложения, НЕ лимит расходов всего
  OpenAI-проекта и НЕ гарантия доступности AI при злоупотреблении: квоту могут исчерпать.
- Дополнительно владелец устанавливает hard spend limit проекта в OpenAI Dashboard.
  Пароль, опубликованный в README, не является защитой от расходования средств.

Не удалять PVC/базу ради нового деплоя: это сбросит защиту. Повышение `AI_MAX_CALLS`
вручную разрешает дополнительные попытки; без согласования владельца не повышать.
Исходники/образ сборки остаются в уникальных `/root/hackalem-qnt-build.*` для проверки;
удалять только конкретные проверенные каталоги после завершения соревнования.

## Проверка после выкладки

1. HTTPS, `/api/health` (66 профилей), `/api/options`, загрузка UI без моков.
2. Плотная/редкая/нулевая выдача, отсутствующая категория, изменение даты.
3. `explanation_mode=ai` у успешного реального запроса; повтор из кеша.
4. Счётчик в `/app/state/ai_usage.sqlite3` растёт только при обращениях к модели.
5. Открытие на физическом телефоне и в инкогнито; это отдельная ручная проверка.

Перед выпуском скрипт печатает предыдущий образ. Для отката использовать
`kubectl -n hackalem-qnt rollout undo deployment/hackalem-qnt` либо вернуть
конкретный предыдущий образ. Учесть: откат на старый каркас также убирает новую
защиту расходов, поэтому перед таким откатом отключить AI. Не удалять Secret/PVC.
