# Промпт для Codex Бекзат

Я Бекзат (GitHub AbaevnaBeka), работаю с Естаем (Adventkz) в команде QNT на HackAlem AI. Выбрали №6 Firebird — «Умный подбор подрядчиков». Ты отвечаешь за интерфейс и пользовательскую проверку. MVP: форма параметров мероприятия → до 3 подрядчиков с индивидуальными доказательными объяснениями. Никаких бронирований, оплаты и регистрации.

Сначала прочитай docs/PLAN.md и docs/API_CONTRACT.md в командном репозитории https://github.com/BAITC-Hacks/hack-6fc77c04-qnt. Если файлов ещё нет, попроси Естая опубликовать их или прислать оба файла; не придумывай свой контракт. Проверь git status и remote. Создай ветку feat/contractor-ui от общего стартового коммита с этими документами. Не переписывай существующие изменения и не используй force-push.

Твоя зона редактирования: ТОЛЬКО frontend/** и docs/UI_QA.md. Не меняй backend, data, корневые README/зависимости/деплой, контракт и план: ими занимается Естай. Сервер и ключи тебе не нужны. Не проси доступ к VPS или API-ключ в чате. Если frontend ещё отсутствует, создай минимальное React/TypeScript/Vite приложение внутри frontend с npm run dev и npm run build. Все его зависимости и lockfile — внутри frontend. Для совместимости с общей сборкой результат npm run build — frontend/dist. Прокси /api на локальный backend http://127.0.0.1:8000; URL не зашивать в компоненты.

Сделай один понятный экран:
1. Город, дата, формат мероприятия, категория, бюджет на одного подрядчика в тенге; необязательные язык и часы.
2. Ясная кнопка подбора, загрузка, валидация, сетевые ошибки.
3. До 3 карточек: имя, категория, город, цена «от», объяснение 1–2 предложениями, раскрываемые факты-основания, отметки synthetic/city_imputed/price_imputed и ai/local. Не показывай local как AI.
4. Три различимых исхода из контракта. При одной/двух карточках — сообщение почему их меньше. При пустой выдаче — объяснение и возможность изменить условия, не пустой экран.
5. Готовые примеры из PLAN.md: ведущие осенью, редкие флористы, пустой результат. Смена даты и повторный запрос должны быть удобны для показа.
6. Адаптивная вёрстка для телефона, связанные label/input, клавиатура, контраст; русский язык UI. Без тяжёлой графики и лишних разделов.

Подключай GET /api/options и POST /api/match строго по контракту. Не делай собственную сортировку, бизнес-фильтры или запросы к OpenAI/NVIDIA в браузере. Не отображай текст как небезопасный HTML. Защити UI от устаревшего ответа при быстром повторном запросе.

Пока backend не готов, добавь соответствующие контракту фикстуры внутри frontend и явный VITE_DEMO_MODE=true. Постоянно показывай баннер «Демонстрационные ответы интерфейса». В обычном запуске режим выключен. Ошибка настоящего API не должна незаметно заменяться фиктивным успехом. Моки не выдавай за настоящие данные или AI. Никакие секреты в VITE_*.

В docs/UI_QA.md запиши команды запуска/сборки UI, проверенные сценарии, способ переключения на реальный API, фактические результаты и непроверенные пункты. Проверь сборку и доступные тесты, затем сценарии на телефоне/узком экране. Отсутствие работающего backend явно отмечай, но разработку UI на согласованных фикстурах продолжай.

Делай содержательные коммиты только своей работы под моим реальным Git-авторством. Не подставляй Естая или другого автора. Перед коммитом проверь diff и отсутствие секретов. Перед push согласуй со мной публикацию, если такого поручения ещё не было. Передай Естаю имя ветки, commit hash, команды, результаты проверки и известные проблемы. Не меняй main самостоятельно и не выполняй деплой.
