# QNT Contractor Match — Firebird

HackAlem AI, кейс №6. Естай (`Adventkz`) и Бекзат (`AbaevnaBeka`).

Заказчику мероприятия нужен не длинный каталог, а короткий список подходящих подрядчиков с понятными основаниями выбора. Сервис принимает параметры события и возвращает до трёх карточек из исходных 66 профилей. Занятый, слишком дорогой или не соответствующий условиям подрядчик не может попасть в выдачу по решению модели.

## Быстрый запуск без аккаунтов и ключей

Python 3.10–3.12; локально проверяем на 3.10, CI настроен на 3.12. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Windows PowerShell: вместо `source` используйте `.venv\Scripts\Activate.ps1`. Для сторонней локальной сети не открывайте порт без необходимости. API-документация: http://127.0.0.1:8000/docs . Она позволяет проверить весь сценарий без frontend.

Чтобы открыть полный интерфейс с того же адреса, перед запуском сервера соберите frontend (Node.js 22.12+):

```bash
cd frontend
npm ci --no-audit --no-fund
npm run build
cd ..
```

Деморежим по умолчанию выключен; не задавайте `VITE_DEMO_MODE=true` для проверки интеграции. После сборки запустите/перезапустите сервер командой выше и откройте http://127.0.0.1:8000/ . Для разработки UI отдельно: `cd frontend` → `npm run dev`, запросы `/api` проксируются на сервер 8000. Бекзат на Windows использует `npm.cmd`, если политика PowerShell блокирует `npm.ps1`.

```bash
curl http://127.0.0.1:8000/api/health
curl http://127.0.0.1:8000/api/options
curl -X POST http://127.0.0.1:8000/api/match \
  -H 'Content-Type: application/json' \
  -d '{"city":"Алматы","date":"2026-10-10","event_format":"корпоратив","category":"Ведущий","budget_kzt":1000000,"language":"русский","duration_hours":4}'
```

## Как устроен подбор

1. Валидация: известные справочники, календарное окно, положительный целый бюджет, положительные часы. Числа-строки, булевы числа, лишние поля и некорректные даты не принимаются.
2. Город + категория определяют исходный список. Отсутствующая категория — отдельный исход `category_missing`.
3. Последовательные фильтры: занятость → формат → бюджет → язык → длительность. Язык/часы проверяются только если заданы. `max_hours=null` — ограничение неприменимо.
4. Порядок: прямое упоминание формата в описании (1 перед 0), цена по возрастанию, ID по возрастанию. Упоминания определяются фиксированными словесными шаблонами из [плана](docs/PLAN.md), а не моделью. Это эвристика приоритета, НЕ рейтинг качества или вероятность успеха.
5. Возвращаем первые три карточки. `eligible_count` — число подходящих до ограничения тремя, `returned_count` — число показанных.
6. Каждый исключённый кандидат учитывается ровно один раз — по первому проваленному фильтру. Сумма исключённых + подходящих равна исходному списку. Funnel можно восстановить из этих счётчиков без повторного подсчёта на frontend.

Три исхода: `matches_found`, `category_missing`, `no_matches`. Отсутствие результата не является серверной ошибкой. Пустая/короткая выдача сопровождается причинами и предложением изменить ограничения, но система не меняет их сама. API-контракт: [docs/API_CONTRACT.md](docs/API_CONTRACT.md).

## Доказательства и AI

Каждая карточка содержит структурированные факты и точную цитату описания, если есть подходящий фрагмент. Явные упоминания цен, языков и часов в свободном тексте исключаются из цитат: для этих ограничений авторитетны структурированные поля.

Локальный режим выбирает релевантный фрагмент детерминированно. AI-режим отправляет уже отобранных кандидатов и ограниченный список пронумерованных цитат в OpenAI Responses API. Модель выбирает индекс цитаты для каждого кандидата. Сервер проверяет полноту, ID, диапазон индексов и дубликаты; финальный текст строит код из проверенных фактов и исходной цитаты. Произвольный текст модели не попадает в рекомендации. AI не меняет порядок карточек и не вызывает инструменты.

`explanation_mode=ai` означает, что цитату выбрала модель (включая кеш успешного выбора); `local` — что использован локальный алгоритм. Синтаксическая валидность ответа AI не доказывает качество выбора: оценку релевантности проверяем отдельно на демо. Тексты описаний — утверждения исходного каталога, не независимо проверенные рекомендации.

### Включение OpenAI

Создайте локальный игнорируемый `.env` по `.env.example`, заполните ключ только локально и перезапустите сервер. Либо задайте переменные через серверный Secret:

- `ENABLE_AI=true` — разрешить реальные запросы.
- `OPENAI_API_KEY` — серверный ключ (не передавайте его в общий чат).
- `OPENAI_MODEL=gpt-4.1-mini` — начальная конфигурация, доступность для выданного ключа нужно подтвердить реальным запросом.

Модель поддерживает Structured Outputs согласно [официальной странице](https://developers.openai.com/api/docs/models/gpt-4.1-mini); формат запроса проверен по [документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Это не утверждение, что доступ по промокоду уже проверен.

Один запрос на выдачу, общий AI-таймаут 6 секунд, без повторных сетевых попыток. Не более двух одновременных запросов и 12 запросов в минуту на процесс; при превышении — local. После ошибки 30 секунд локального режима. Кеш до 128 успешных запросов. При пустом ключе/ошибке/отказе/невалидном ответе модель не блокирует подбор. `store=false`; отправляются только параметры события и анонимизированные фрагменты каталога. Ключ не присутствует в health, ответах API, браузере и репозитории.

## Проверка и демо

```bash
source .venv/bin/activate
cd backend
python -m pytest -q
cd ..
python backend/scripts/demo_check.py
```

Автотесты проверяют целостность каталога и его SHA-256, граничные значения, все фильтры, занятость площадок, три исхода, детерминизм, изменение даты, API-контракт, ошибки ввода, точность цитат и отказы AI. Отдельная проверка инвариантов проходит по 66 профилям на трёх датах. Тесты не требуют внешней сети.

Воспроизводимые запросы:

| Сценарий | Параметры | Ожидаемое |
|---|---|---|
| Плотная категория | Алматы, Ведущий, корпоратив, 10.10.2026, 1 млн ₸, русский, 4 ч | 4 подходящих, 3 карточки |
| Смена даты | Тот же запрос на 11.10.2026 | Другой набор/порядок тройки из-за календаря |
| Редкая категория | Алматы, Флорист, свадьба, 10.10.2026, 300 тыс. ₸, без языка/часов | 1 карточка HK-39372 |
| Нет подходящих | Первый запрос с бюджетом 1 000 ₸ | `no_matches` с причинами |
| Нет категории | Зарубежье, Флорист, свадьба, 10.10.2026, 300 тыс. ₸ | `category_missing` |

Любая смена даты не обязана менять выдачу; проверяем конкретную воспроизводимую пару дат. Время реального AI и пользовательский сценарий на телефоне требуют отдельной проверки после интеграции.

## Интерфейс и развёртывание

Бекзат владеет `frontend/**` и `docs/UI_QA.md`; Естай — сервером, каталогом и деплоем. Общий контракт не меняется односторонне. Клиент использует относительный `/api` и dev-прокси на порт 8000. Промпт Бекзат не изменён.

Подготовлены два варианта контейнерной сборки, пока не проверены:

```bash
# Только API, из корня репозитория:
docker build -f backend/Dockerfile -t qnt-api .
docker run --rm -p 8000:8000 qnt-api
# После интеграции frontend (требуется frontend/package-lock.json):
docker build -f Dockerfile.prod -t qnt-firebird .
```

Основной локальный запуск нативный, Docker не требуется. Полный контейнер обслуживает frontend и API с одного адреса. При production-сборке UI-моки выключены. Push в GitHub не выполняет деплой автоматически. CI настроен на тесты/сборку frontend и тесты backend после сборки UI без секретов; успешная локальная проверка не заменяет результат CI и публичную проверку.

## Ограничения и развитие

- Только предоставленный каталог, не поиск по интернету. 66 профилей, вымышленные имена, 13 синтетических записей и дополненные цены/города. Метки сохраняются в `flags`.
- Цена «от» за одного подрядчика на мероприятие; это не смета всего события.
- Календарь ограничен 23.09–31.12.2026. Отсутствие даты в `busy_dates` означает только отсутствие отметки о занятости, не подтверждённую доступность и не бронь.
- Свободные описания могут содержать маркетинговые утверждения; используем их с атрибуцией.
- Лексический приоритет прост и прозрачен, но не понимает все синонимы и отрицания. Нельзя подавать его как объективный рейтинг.
- Ограничитель запросов и кеш работают на один процесс; для масштабирования понадобятся общие лимиты/кеш, актуальные календари, подтверждённые цены и оценка качества объяснений на размеченных запросах.
- Регистрация, бронь, оплата, заявки и уведомления намеренно вне MVP.
